# 高架桥数据前置探查

## 两个路径是否为同一份

不是同一份，也不是软链接。

| 路径 | 设备号 | inode | 内容概况 |
|---|---:|---:|---|
| `/root/autodl-tmp/高架桥数据` | 2304 | 30070786264 | 主数据集，含视频、标注与实验派生文件 |
| `/root/autodl-tmp/HolmesVAU-master/autodl-tmp/高架桥数据` | 2304 | 24734844903 | 仅有 `traffic_test_pred.jsonl` 与 `traffic_test_summary.json` 两个旧结果文件，无视频 |

两者 `realpath` 保持各自路径，inode 不同；嵌套路径不是主数据的副本。

## 视频盘点方法

对主路径下全部 12,584 个 MP4 用 OpenCV 仅读取容器/视频流元数据（帧数、fps、宽高），时长按 `frame_count / fps` 计算。成功读取 12,557 个，27 个位于 `video/` 的源文件因缺失 `moov` 或解码/容器错误无法取得有效媒体头；这些失败未被丢弃。全量扫描日志见 `logs/probe-bridge.log`。

### 原始长视频

主源目录 `video/` 有 6,244 个 MP4，其中 6,217 个媒体头有效、27 个失败。按 SPEC 的 `> 60s` 判据，存在长视频：

- 有效源视频：6,217
- 时长 > 60s：1,191
- 时长 <= 60s：5,026
- 有效源视频时长 min / median / max：4.920 / 59.960 / 1174.720 秒
- 分辨率分布：2560×1440（5,301）、1920×1080（830）、2048×1536（63）、4096×2160（21）、960×540（1）、854×480（1）
- fps 主体为 25.0（6,032）；另有 25.4（137）、25.067（31）及少量约 23–25.467 的文件

目录和标注没有“未裁剪”布尔字段；因此只能确认 `video/` 是相对于 `video_fixed/` 的源文件目录、其中确有 >60s 文件，不能仅凭目录名证明每个长文件都是完整连续录像。部分源文件存在时间基/容器问题：对应的 `video_fixed/` 清洗副本中只有 107 个仍 >60s，故使用原始时长时应保留这一质量警告。

## 相机数量 / 相机 ID

不能从当前结构可靠统计相机数量或建立稳定相机 ID：

- `video/` 与 `video_fixed/` 都是扁平目录，没有按相机分目录。
- 文件名格式为 `类别_YYYYMMDDhhmmss_事件来源_数值ID.mp4`；末尾数值随事件变化，结合标注看更像事件/记录 ID，而不是相机 ID。
- 现有自由文本答案偶尔出现“枪机1”“定焦13”和具体路段名，但没有独立结构化 `camera_id` 字段，命名也不足以无歧义归一化。

因此可推断存在多路固定监控相机，但不能据此给出可信的相机总数或 ID 清单。

## 夜间 / 雨天 / 遮挡线索

没有发现结构化的天气、昼夜或遮挡字段，目录名和文件名也没有 `night/rain/occlusion` 或“夜间/雨天/遮挡”等标记。但存在以下可推断线索：

1. 文件名自带 `YYYYMMDDhhmmss`，可按小时做昼夜启发式判断，但它不是显式昼夜标签。
2. `traffic_train.jsonl` / `traffic_test.jsonl` 的 GPT 答案自由文本中有环境描述：
   - “夜间”：922 / 221 条
   - “雨天”：120 / 28 条
   - “阴雨”：40 / 7 条
   - “路面湿滑”：159 / 36 条
   - “遮挡”：398 / 109 条
3. “遮挡”在自由文本中常用于“施工设施遮挡车道”，不等价于视觉遮挡标签；夜间/雨天描述同样是自然语言内容而非人工结构化标记。

结论：夜间与雨天可以通过时间戳和已有自由文本作弱推断；视觉遮挡没有可靠标签，不能把关键词命中直接当作遮挡真值。
